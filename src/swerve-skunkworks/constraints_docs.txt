# AprilTag Constraint System Documentation

## What is a Constraint?

A constraint is a rule or limitation that modifies the robot's movement when an AprilTag is detected. 
It acts as a virtual boundary or guide that helps the robot maintain specific spatial relationships 
with AprilTags in its environment. Constraints are particularly useful for:

- Preventing collisions with field elements
- Maintaining optimal positioning for scoring
- Ensuring consistent approach angles
- Creating virtual boundaries or keep-out zones

## How Constraints Work

1. **Detection**: When an AprilTag is detected by the Limelight, the constraint system becomes active
2. **Evaluation**: All applicable constraints are evaluated in priority order
3. **Application**: Each constraint modifies the desired movement to stay within its bounds
4. **Combination**: The final movement is a combination of all active constraints

## Constraint Types

### 1. DistanceConstraint
Maintains a specific distance range from an AprilTag.

```java
new DistanceConstraint(
    tagId,          // int: AprilTag ID (-1 for any tag)
    minDistance,    // double: Minimum allowed distance (meters)
    maxDistance,    // double: Maximum allowed distance (meters)
    influenceDist,  // double: Distance at which constraint starts affecting movement
    priority        // int: Constraint priority (higher = applied first)
)
```

### 2. MaintainOffsetConstraint
Maintains a specific 2D offset from an AprilTag.

```java
new MaintainOffsetConstraint(
    tagId,          // int: AprilTag ID (-1 for any tag)
    offset,         // Translation2d: Desired (x,y) offset from tag
    tolerance,      // double: Position tolerance (meters)
    influenceDist,  // double: Distance at which constraint activates
    priority        // int: Constraint priority
)
```

### 3. RotationConstraint
Limits the robot's rotation relative to an AprilTag.

```java
new RotationConstraint(
    tagId,          // int: AprilTag ID (-1 for any tag)
    minAngle,       // double: Minimum allowed angle (radians)
    maxAngle,       // double: Maximum allowed angle (radians)
    influenceAngle, // double: Angle at which constraint starts affecting rotation
    priority        // int: Constraint priority
)
```

## Priority System

Constraints are applied in order of their priority (highest to lowest). When multiple constraints are active:
1. Higher priority constraints are applied first
2. Lower priority constraints can only further restrict movement
3. Conflicts are resolved in favor of higher priority constraints

## Example Setup

// Keep 1-2m from tag ID 3
constraintManager.addConstraint(new DistanceConstraint(3, 1.0, 2.0, 3.0, 10));

// Maintain 1.5m in front of tag ID 4
constraintManager.addConstraint(new MaintainOffsetConstraint(
    4, new Translation2d(1.5, 0), 0.1, 2.0, 20));

// Limit rotation to ±30° relative to tag ID 5
constraintManager.addConstraint(new RotationConstraint(
    5, -Math.PI/6, Math.PI/6, Math.PI/4, 15));

## Troubleshooting

- **Robot not moving as expected**: Check constraint priorities and influence distances
- **Oscillation near boundaries**: Reduce the influence distance or add damping
- **Constraints not activating**: Verify AprilTag detection and tag IDs
- **Unexpected behavior**: Check for conflicting constraints with similar priorities

## Field-Relative Driving

The constraint system is designed to work with field-relative driving. Ensure your swerve drive is properly configured for field-relative control before using constraints.

 * constraintManager.addConstraint(new DistanceConstraint(
 *     3,      // Tag ID
 *     1.0,    // Min distance (m)
 *     3.0,    // Max distance (m)
 *     4.0,    // Influence distance (m)
 *     10      // Priority (higher = applied first)
 * ));
 * 
 * // Maintain a specific offset from tag ID 4
 * constraintManager.addConstraint(new MaintainOffsetConstraint(
 *     4,                          // Tag ID
 *     new Translation2d(1.5, 0),  // 1.5m in front, 0m to the side
 *     0.1,                       // 10cm position tolerance
